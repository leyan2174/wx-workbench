# 编译告警维护

- 无调用方的实现可删除；先检查正式入口、测试、构建与发布依赖，不增加假引用消除告警。
- 测试专用入口、常量和 re-export 使用 `cfg(test)`，夹具调用真实受检实现，不替换成成功 stub。
- 必须保留的业务契约成员可以逐成员使用带理由的 `expect(dead_code)`。来源不完整、分页未结束和阶段失败不能为了消除告警而混同为成功空值。
- 当生产调用使预期不再成立时，应处理 `unfulfilled_lint_expectations` 并移除对应标注。
- 独立夹具嵌入生产模块时，可达性与正式二进制不同。仅在具体引入点说明例外，不关闭整个程序的 warnings。见[夹具告警归属](../tests/support/WARNINGS.md)。

检查入口见[质量检查](quality-checks.md)。独立夹具按照[检查矩阵](../tests/support/CHECK_MATRIX.md)中的有效目标执行；不要通过复制整个应用或删除断言让检查通过。日志留在仓库外，不提交构建缓存、配置、密钥或私人数据。
