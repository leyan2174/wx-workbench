# 增量归档边界

`business::archive` 负责增量目标去重、闭区间请求、响应目标核对、逐目标结果及批次完成。数据源与发布器通过窄接口接入；原始导出文档是不透明负载，不是普通消息业务对象。该模块没有 SQLite、JSON、daemon 或具体微信适配器依赖。

现有 `export-delta` 与 `export-all --mode delta` 通过同一用例执行。执行宿主仍使用固定 `RuntimeContext` 的既有查询传输；请求不能切换账号。IPC 原始 `DeltaChat`、元数据警告及旧 JSON 投影留在边界。源响应 username 不匹配会记录失败，不会导出到另一目标。目标去重不等于消息去重，原始重复消息和既有增量 UID 格式保留；UID 是归档产物标识，不能当作跨库稳定消息身份。

## 发布与失败

- 生产宿主传入固定账号的配置、密钥、数据库、缓存和运行目录保护路径。创建批次之前、每个文件发布之前均检查保护边界。
- `DeltaRunWriter` 复用共享 `ExportTarget::new_file`，使用私有临时文件、父目录身份守卫、同步与不覆盖提交。删除原有独立临时文件发布实现。
- 追加只复用导出根和 `deltas` 目录，批次目录必须全新。同名批次即使没有清单，也不会被恢复或覆盖。
- 每个目标读取或发布失败仍记入清单，继续处理其他目标；不会用空成功掩盖失败。清单最后提交，提交失败返回错误，不产生“本轮已完成”结果。
- 单个产物原子提交，不承诺整个目录事务性。中途失败或取消可能留下已提交文件；没有完成清单的目录不是已提交的增量检查点。
- CLI 与任务 worker 保留原退出码、输出、取消及进程回收边界。未新增归档数据库、重试服务或任务状态机。

## 验证范围

业务模块使用内存源和发布器测试身份拒绝、去重、部分失败及清单失败。真实文件集成沿用 `toolkit::chat_delta` 与 `daemon::operations::export_delta` 的合成 golden 数据、旧文件保护、目录联接/竞争和失败清单测试，并增加受保护根目录与文件冲突测试。运行结果以本阶段验收记录为准，不能仅凭内存测试断言发布成功。

本切片不宣称已将全量目录渲染、所有格式投影和媒体处理编排迁入业务层；这些原有能力继续使用既有入口与受保护的暂存发布机制。
