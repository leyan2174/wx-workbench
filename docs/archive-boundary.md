# 归档业务边界

## 全量与合并归档

`business::archive::export_chats` 规定逐目标的准备输出、读取、身份核对、转换、再次身份核对、文件发布和索引登记顺序。`FullArchive` 是该批量用例的窄接口，不是通用任务执行器。文档负载保持不透明；业务层不读取 JSON 字段、微信列名或文件路径。

现有 `export-chats` 与 `export-all` 的全量路径接入同一用例。宿主装配固定 runtime 的查询 RPC、应用层 `ChatIndex`、原始文档过滤/合并和可选转写回调。时间条件只过滤本次追加，不删除历史归档消息；转换后仍按既有规则重算日期范围。回调不能改变目标身份。显式 username 筛选使用同一业务函数，不按显示名猜测身份；部分命中继续，全部未命中拒绝，原目标顺序和 CSV 选择顺序保留。

结果保留逐阶段错误。只有文件发布且索引登记成功才计入 `written` 字段；文件已发布但索引失败时，失败项增加 `artifact_published: true`，不假装没有产物，也不报告完整成功。`ChatIndex` 先发布候选索引，成功后才更新内存状态；发布失败不能推进当前文件指针。

现有 `_export_index.json` 增加 `runtime_binding`，在任何聊天文件发布前写入。绑定使用当前 `RuntimeContext.id`，已绑定目录不能被另一个运行上下文复用，避免相同 username 的不同账号归档混写。影响运行身份的配置路径变化也会被保守拒绝，可选新的导出目录，不会静默换绑。

旧未绑定归档按原兼容方式读取；检测到旧索引或旧记录时，索引及批次结果标记 `legacy_unverified: true`。这不证明旧文件属于当前账号，也不自动把旧记录升级为严格证据。损坏、不可读、未知版本或绑定结构无效的索引明确拒绝，不再静默回退到目录扫描；只有索引不存在时才执行既有旧文件发现。该索引是原来的归档产物索引，不是新任务数据库。

## 增量批次

`business::archive` 负责增量目标去重、闭区间请求、响应目标核对、逐目标结果及批次完成。数据源与发布器通过窄接口接入；原始导出文档是不透明负载，不是普通消息业务对象。该模块没有 SQLite、JSON、daemon 或具体微信适配器依赖。

现有 `export-delta` 与 `export-all --delta-only` 通过同一用例执行。执行宿主仍使用固定 `RuntimeContext` 的既有查询传输；请求不能切换账号。IPC 原始 `DeltaChat`、元数据警告及 JSON 投影由 `application::chat_delta_export` 管理。源响应 username 不匹配会记录失败，不会导出到另一目标。目标去重不等于消息去重，原始重复消息和既有增量 UID 格式保留；UID 是归档产物标识，不能当作跨库稳定消息身份。

## 发布与失败

- 生产宿主传入固定账号的配置、密钥、数据库、缓存和运行目录保护路径。创建批次之前、每个文件发布之前均检查保护边界。
- `DeltaRunWriter` 复用共享 `ExportTarget::new_file`，使用私有临时文件、父目录身份守卫、同步与不覆盖提交。
- 追加只复用导出根和 `deltas` 目录，批次目录必须全新。同名批次即使没有清单，也不会被恢复或覆盖。
- 每个目标读取或发布失败仍记入清单，继续处理其他目标；不会用空成功掩盖失败。清单最后提交，提交失败返回错误，不产生批次完成结果。
- 单个产物原子提交，不承诺整个目录事务性。中途失败或取消可能留下已提交文件；没有完成清单的目录不是已提交的增量检查点。
- CLI 与任务 worker 保留原退出码、输出、取消及进程回收边界。

聊天目录与朋友圈目录共用 `infrastructure::output_tree`，它只负责输出树的文件系统发布与来源绑定。它保留已有绑定文件、锁文件名、显式 adopt/update 策略及逐文件提交语义，不宣称整个目录可以事务回滚。单文件 `ExportTarget` 与目录发布是不同接口，但继续复用相同路径保护基础；`write_bytes_checked` 在写入同步后复核业务证据，再做最终目标/父目录检查。

## 验证范围

业务模块使用内存实现测试阶段顺序、两次身份核对、失败后继续、未发布时不登记索引、索引失败时保留产物状态，以及增量去重/清单失败。真实文件集成沿用全量与增量导出的合成 golden 数据、旧文件保护、目录联接/竞争和失败清单测试，以及受保护根、文件冲突、证据回调失败以及文件锁导致索引提交失败的场景。运行方式见[测试说明](../tests/README.md)，内存测试不代替真实文件发布检查。

原始归档格式投影、HTML 渲染和媒体处理是明确的边界能力，不把原始导出 JSON 当作普通消息业务对象。全量与增量工作流均不改变 daemon 的任务恢复语义；`interrupted` 不是自动断点续跑。
