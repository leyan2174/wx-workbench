- 消息统计、原始导出及诊断复用消息适配器快照；原始来源信息保留在明确的诊断或导出边界。

- 表情目录和批量选择使用表情适配器及业务接口；本地旧消息摘要匹配不宣传为授权目录证据。
- 全量归档使用 `business::archive` 的阶段编排；发布前绑定运行上下文，发布后才记录聊天成功。已有文件发布但索引失败单独报告。

- CLI 启动转发垫片移除，Web 启动参数使用 service 的非 clap 契约。
- 批量原始语音导出使用独立业务选择和共享语音目录适配器，产物及汇总经固定运行上下文的共享发布器。目录目标的物理表名验证和精确选择迁入消息适配器。
- 计划 CSV、离线 SNS 视频和密钥验证样本的最终产物接入共享发布器；样本保留先暂存、保存密钥成功后发布的顺序。Web 模块恢复为普通 `web/mod.rs`，静态资源路径不变。

## 首轮失败与处理

1. 归档身份失败测试原先断言索引不存在。新增账号绑定需要先持久化绑定，现改为精确断言只有本账号绑定、聊天索引为空且聊天文件不存在；没有放宽失败不推进导出状态的要求。
2. 增量导出在反向时间窗口的合成夹具上返回 `invalid message evidence`。适配器已恢复旧空结果语义，同时保留 schema 校验；最终根测试已通过。
3. 图片列表误用了严格解码的跨类型歧义规则。已恢复列表原有完整类型区分，严格解码的拒绝规则和旧安全断言保留；真实 MCP 进程测试已通过。

## 验收剩余项与边界

- 下一阶段继续收拢 `toolkit/contact_metadata.rs` 的原始联系人元数据、`toolkit/chat_plan.rs` 的导出容量统计和 `toolkit/audio/batch.rs` 的批量音频读取。这三处生产代码仍直接包含微信 SQL；不能仅凭普通查询或严格 MCP 语音已迁移就宣称所有入口完成。
- 本阶段已完成根工作区及受影响独立夹具验证；下一阶段的源码修改仍须重新验证，不能沿用本记录声称通过。
- 旧无绑定归档仅标记 `legacy_unverified`，不是对历史账号归属的证明；损坏索引不静默回退。
- 目录发布不是整个文件树事务；已发布文件不会因后续取消或失败自动回滚。
- daemon 重启后的 `interrupted` 不是自动断点续跑；MCP 断连不等于显式取消持久任务。
- 忽略项不算通过。当前 Windows 用户已被恶意代码控制的情况不由路径保护或 DPAPI 隔离。
