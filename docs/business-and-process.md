# 业务结果与受管进程

## 业务结果

`ipc::outcome::BusinessOutcome` 是内部分类，不改写旧查询的
`ok`、`error` 和展开数据结构，也不新增统一外层包装。

| 分类 | 含义 | typed worker 退出码 |
| --- | --- | --- |
| Success | 本次业务完成 | 0 |
| Partial | 有成功结果，但仍有失败或未完成部分 | 20 |
| Refused | 业务前置条件不满足或请求被拒绝 | 21 |
| Failure | 业务失败 | 1 |

连接、超时、帧解析等错误仍属于传输或协议层，不等同于业务失败。
分类只检查约定的顶层标记，不递归猜测聊天内容或任务详情。
查询一个失败任务可以是成功的查询，不会因任务状态而被重新分类。

- MCP 将非成功业务结果映射为 `isError: true`，不假装后端断连。
- Web 将 Partial 映射为 409，Refused/Failure 为 422，传输不可用为 503；
  原有繁忙和授权判断独立保留。
- 任务终态仍为 `succeeded`、`failed`、`cancelled`；部分成功任务记录为
  `failed` 并保留退出码 20，不新增破坏旧消费者的终态。
- CLI 保留旧查询歧义退出码 2。没有返回 typed 错误的旧业务退出码
  不自动改写；首次运行等既有特殊退出码也保持原约定。

`BusinessFailure` 只携带分类、可选旧数字退出码和白名单诊断枚举。
typed 公开错误使用固定文本，不转发底层错误链。密钥库缺失、不支持的材料格式、
格式损坏、账号不符、保护失败、冲突、繁忙和路径错误分别有安全诊断；
损坏或账号不符不会伪装成“没有密钥”，也不会启用明文回退。

Decrypt（包括 task WechatDecrypt）有成功项又有失败项时返回 20，
全部失败返回 1。当前只有这一套严格解密契约，调用方仍应读取类型化汇总以处理部分结果。既有无密钥图片跳过规则保持不变，
缺钥跳过不充当成功项。
非 typed 错误和原有报告的脱敏不由分类器自动保证，不能据此宣称全局脱敏完成。

## 受管执行

`windows_process::managed` 在 Windows 创建挂起子进程，先加入 Job Object
再恢复执行，避免启动到归属建立之间的空隙。普通 helper 不使用 breakaway；
worker 内的 helper 使用嵌套 Job，内层清理不应杀死外层 worker。
已有专用账号捕获流程的特殊 Job 行为不在此处扩大使用范围。

执行使用绝对总期限、取消检查和输出上限，轮流读取 stdout/stderr，
不会用无限等待冒充取消。即使根进程已退出，也清理其仍存活的后代。
清理等待有界；未确认清理成功时返回失败，不声称实际子进程已经终止。

- 图片、视频处理按调用方的期限与输出限额运行受管子进程。
- task worker：所有步骤共用 24 小时总预算，每步合计输出最多 64 MiB。

发布仍使用临时文件和原子替换；正常错误及发布失败保留旧有效输出。
强制杀死整个 worker 不会运行 Rust 析构函数，因此不能保证临时文件已删除：
宿主必须在确认进程清理后处理遗留临时文件。Job 终止不是文件事务回滚。

实现补充见 [业务分类](../src/ipc/OUTCOMES.md) 和
[Windows 进程生命周期](../src/windows_process/README.md)。
