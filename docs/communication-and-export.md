# 查询通信与导出文件保护

## 查询协议 v3

查询仍使用账号专属的 `wx-cli-v2-<runtime_id>` 管道名，名称中的 v2 是运行命名空间，不是查询报文版本。任务服务继续使用独立的 v1 长度前缀协议和认证令牌；两条业务通道没有合并。

发送业务请求前，客户端复用 `service::client::connect_named`，通过实际连接句柄获取服务端 PID，并对照固定账号的身份记录检查 PID、进程出生时间、可执行文件及存活状态。随后读取服务端 `QueryHello`，核对 `version=3` 和 `runtime_id`；校验失败不发送业务数据。

查询报文均为换行结束的 JSON：

- 服务端先发送 `QueryHello { version, runtime_id }`。
- 客户端发送 `QueryEnvelope { version, runtime_id, response_limit, request }`。
- 服务端发送 `QueryReply`，`result=response` 时包含原有业务 `Response`；`result=oversize` 表示传输预算拒绝。响应也必须匹配版本和账号运行身份。

**不支持旧裸查询报文，不静默回退。** 新客户端连接旧 daemon 会明确失败；应显式停止旧 daemon，再由当前版本重新启动。不能为了升级而盲目覆盖活跃后台的身份记录。

## 帧与期限

`service::transport::framing` 共用换行帧和 u32-LE 长度前缀帧的完整性及限额检查。EOF、截断、超限、无效预算、协议错误、超时和 I/O 错误可区分；超限检查先于 JSON 解析。取消由监控既有取消类型表示。

| 查询预算 | 上限 |
| --- | --- |
| 请求（包含信封和换行） | 64 KiB |
| Ping 响应 | 1 KiB |
| 普通响应默认值 | 32 MiB |
| 旧全量聊天/目录导出响应 | 256 MiB |
| 所有帧的硬上限 | 256 MiB |

调用方可以降低响应预算，服务端还会限制到对应操作上限。查询响应预算包含外层信封。大结果应使用现有分页或文件产物入口，不能把响应限额改成无限大。

普通查询期限默认 300 秒，可通过 `WX_CLI_REQUEST_TIMEOUT_SECS` 设置，最大 3600 秒；启动等待消耗同一次调用预算。连接、握手、写入、读取共用剩余期限，不逐层重新计时。服务端连接总期限最大 3600 秒，初始握手/请求阶段最多 5 秒。

任务客户端保留整次调用期限，任务服务端设置 80 秒连接总上限，并保留较短的阶段上限。任务提交超时可能已经执行，重试必须复用原幂等键。监控仍只连接现有后台，外层取消/总期限覆盖小请求和分块请求；必要的取消清理另有最多 1 秒预算。停止等待不代表已派发的数据库或任务工作已经终止。

## 导出保护与发布

`infrastructure::publication::{export_protected, validate_export_target, ExportTarget}` 固定账号的配置、新密钥存储、旧 `keys_file`、暂留的 `account_key.dpapi`、密钥更新锁、原始数据库、解密目录及运行目录。尚不存在的受保护路径也不能作为导出目标；目录导出不能包含这些资源。重解析点及多硬链接目标由现有路径守卫拒绝。

分页 `export`、单聊和批量聊天导出复用此边界。分页参数、筛选条件和输出格式不变；标准输出分支不创建导出文件或临时文件。数据库、目录导出、ASR 输出和监控状态文件均保护正式密钥路径；解密只依赖正式存储，不要求旧密钥文件存在。

单文件发布复用 `infrastructure::publication::check_target`、`infrastructure::publication::parent_guard`、`HostOutputGuard` 和私有临时文件权限。`ExportTarget` 在查询/合并前捕获目标身份和流式摘要；发布前复核，写入失败或检测到并发变更时保留旧文件。新目标使用禁止覆盖的原子发布，已有普通产物按显式导出操作允许原子替换。临时文件同步、关闭写句柄并复核身份后才发布。

配置 `Snapshot` 的 16 MiB JSON 上限不套用到大型导出：导出使用流式序列化/摘要，不整体读取旧产物。路径写入回调可以完成自身的原子替换（例如数据库解密）；外层先关闭暂存写句柄，回调结束后重新打开并核验完成文件，期间保留禁止目录重命名的句柄。单文件最终复核与替换不是跨进程 compare-and-swap；需要严格串行的调用方仍应持有其领域锁。目录、媒体、索引和增量批次保留各自现有发布顺序与失败恢复规则，不把逐文件原子替换宣称为整批事务。

业务结果与受管子进程的语义见 [业务结果与进程生命周期](business-and-process.md)。
