# 测试与整理计划

## 执行顺序

先固定当前工作区并运行一轮完整测试，汇总失败和跳过项，再修改业务代码、文档
及发布内容。已有未提交改动保留，不回退。每项修复先复现问题，再运行对应回归；
整理完成后重新运行完整测试和发布检查。

测试输出保存在仓库外。公开文档只说明当前功能、限制和使用方式，不保存个人账号、
聊天样本、机器路径、阶段日志或历次通过数量。

## 基线范围

| 分组 | 检查内容 | 通过条件 |
| --- | --- | --- |
| Rust | Windows x64 MSVC 编译，主程序及全部已注册集成测试 | 每个套件有退出码；失败不阻止其他套件执行 |
| 可选测试 | 已安装的 FFmpeg、Frida、符号链接能力及其他本地依赖 | 逐项核对前置条件；子进程夹具由父测试调用，不单独启动 |
| 命令行 | 参数校验、查询、导出、增量、媒体、朋友圈、配置、任务和停机 | 既验证返回结果，也检查输出文件、退出码及数据保全 |
| MCP | 初始化、工具清单、实际调用、错误返回、会话隔离和退出清理 | 使用真实协议；有意义的业务结果与普通查询一致 |
| Web | HTTP 鉴权、实际查询、图片状态、SSE、任务表单、关闭行为 | HTTP 与 daemon 链路可用，错误状态可识别 |
| 界面 | 桌面和手机视口、会话选择、筛选、分页、设置、错误展示 | 无空白页、遮挡、横向溢出或未解释的控制台错误 |
| 数据安全 | 固定账号、路径边界、权限、取消、原子发布、缓存失效 | 不越过账号或输出目录边界，不损坏原始数据 |
| 文档 | 功能、命令、配置、依赖、模块图和链接 | 与当前代码一致，无过期入口和机器专属步骤 |
| 公开内容 | Git 跟踪及待加入文件、发布包、二进制附件、Git 历史 | 无私钥、令牌、真实聊天、个人路径或可识别用户的数据 |

同一共享模块可能在多个套件中执行，测试通过次数不等于独立功能数。

## 自动执行与跳过

默认测试只用临时合成数据。已经授权的真实账号验证使用独立配置、密钥副本、运行
目录和输出目录，不改写原始微信数据。真实返回内容只在本机检查，报告只保留必要
的状态、类型和数量。

需要扫码、手机确认、购买服务、补充凭据或新的人工授权时，先记为跳过并继续其他
项目。不得把跳过项算作通过。云端转写没有上传授权时不发送音频；下载、清理和
回写测试只能在其已授权范围内运行。取消与清理测试使用专门创建的临时数据。

可选测试先读测试体，避免把隐藏子进程入口、会重启微信的命令或外部收费调用
当作普通测试批量执行。不要为了通过测试擅自下载模型或关闭安全检查。

## 整理原则

- 先修正确性和数据安全问题，再处理重复逻辑、长函数和难以理解的状态转换。
- 有明确共同语义和多个调用点时才提取公共函数；账号权限、协议适配和业务执行
  的边界不能为减少行数而合并。
- 删除无调用的实现和过期说明前，检查命令入口、测试、构建和发布是否依赖它。
- 注释以中文解释约束、输入输出、异常路径及取舍，不逐行复述赋值和函数名称。
- 文档和注释用直接、具体的表述，去除对话痕迹、宣传语、阶段汇报及重复免责声明。
- 保留开源许可、第三方版权与来源说明；个人信息清理不能删去法定署名。

## 最终验收

修复后的完整回归、文档检查、公开内容扫描和发布文件清单必须共同通过。尚需人工
介入的项目单独列出原因及影响。Git 历史发现敏感内容时，不强制改写或推送历史；
先说明发布风险，提供可审查的处理范围。未经明确要求不提交、不推送、不发布。
