# 联系人与群成员切片

这是全仓业务与微信适配分离的首阶段之一，不代表消息、朋友圈、媒体、收藏或归档均已完成迁移。

## 当前边界

- `business/contacts.rs` 定义账户范围内的 `ContactId`、`Contact`、`Member`、`Tag`、查询页、能力状态和窄只读 `ContactSource`。业务用例负责筛选、分页、显示名优先级、唯一身份选择及成员排序，不依赖 SQLite、微信、daemon、clap 或 JSON Value。
- `adapters/wechat/contacts/mod.rs` 实现接口，仅接受宿主传入的固定账户路径。实际探测联系人、标签和群成员所需表列，解释身份、认证与可见性，读取事务内将数据转换为业务对象。SQL 行号、成员关联编号和标签存储编号不进入业务模型。
- 适配器子模块保留已有群昵称 BLOB 算法和标签字段解析算法。标签标量解析复用现有 `toolkit/contact_metadata` 原语，不另写同类解析器。
- daemon 保留 `DbCache`、查询租约、名称缓存和响应投影。`load_names` 使用业务对象填充原有 `Names`；其他尚未迁移的消息查询仍可使用该缓存。

## 实际接线

普通 contacts、legacy MCP contacts、members、contact tags 和 tag members 均通过联系人业务类型及微信适配器。旧联系人行读取、成员 SQL 与群昵称解析已从 daemon 移除。`contact_rows.rs` 与 `mcp_contacts.rs` 现在只负责兼容投影和固定账户装配，不再包含 SQL 或 BLOB 解析。

保留的协议差异有明确用途：

- 普通联系人只列真人，按显示名、身份排序；搜索显示名和身份。姓名相同时用身份稳定排序。
- 普通联系人消费当前查询租约的 `Names` 物化快照，由微信缓存适配器转换为业务目录，不重新打开数据库或扩大快照范围。这不是数据库读取失败后的回退。legacy 仍明确读取当前账户数据库；两者复用筛选、分页与投影规则，但保留原有来源/代际语义。已物化的首选显示名不会被误标为昵称或备注。
- legacy 联系人保留可见目录范围与源目录顺序，搜索昵称、备注和身份，继续输出原有 `nick_name`、`remark`、`alias`、`description`、`phone`、`display` 字段。可选值在展示边界映射为空字符串。
- legacy golden 中重复 username 的目录项通过显式兼容读取策略保留；普通联系人读取、名称缓存、成员关联与唯一身份选择仍拒绝重复身份，不能依靠目录顺序消除冲突。
- 标签定义的重复 ID 更新、重复关联计数及空标签名维持既有兼容规则。业务唯一标签选择采用不区分大小写的精确匹配优先，不再由入口自选首项。
- 群查询按稳定身份优先，其次唯一名称匹配；同名不再按扫描顺序任选一个。不存在、歧义、格式不支持、数据不可用、损坏数据和限额均为明确错误。

## 完整性与预算

完整成员能力根据 `chat_room`、`chatroom_member` 和联系人关联列实测；群名列支持已存在的三个变体。完整成员为空时保留“完整但空”，不自动用历史消息填充。损坏关联、重复身份或重复群记录均失败，不吞掉错误。

确实缺少完整成员能力时，宿主才加载已知消息分库。结果增加 `membership_complete` 与 `membership_source`：`member_directory` 表示完整成员目录，`observed_senders` 仅表示记录中观察到的发言人。缺失分库、未知分库或无法解析的发言人关联不能伪装成成功空列表。此降级不证明成员目前仍在群内。

适配器保持只读事务与有限预算：联系人最多 100,000 条，单文本最多 4096 UTF-8 字节，累计联系人文本最多 16 MiB。标签保留原有 10,000 定义、100,000 关联、1 MiB 单 BLOB 和 16 MiB 累计文本上限。普通与 legacy JSON 投影继续限制响应文本量。跨库读取不声称具有全局事务一致性。

## 验证与剩余范围

新增业务内存测试覆盖筛选、分页、账户隔离、同名歧义和标签选择；11 项合成 SQLite 测试覆盖能力缺失、列名变体、成员关联损坏、完整空群、历史发言人、重复身份、标签 BLOB、错误分类、读取预算及连接级显示名读取；另有名称缓存适配测试验证快照范围、首选显示名与分类。投影测试比较普通与 legacy 联系人的共同身份与显示名。已有标签与群昵称解析测试继续复用迁移后的实现，空名称缓存仍必须报错。

SNS 导出通过适配器的连接级 `display_names` 读取联系人，不再自行查询联系人列；目录名清理留在导出边界。该接口保留空表为空映射，并可使用调用方已有事务。独立 `contact-rows` 夹具直接导入真实联系人业务、适配器和元数据解析模块，不引入其他业务域或替代实现。

本切片未读取真实账户，未扫描进程或获取密钥。按协作约定由父任务统一编译与运行测试；本文件不声明尚未执行的测试已经通过。

父任务已反馈独立 `business_contracts` 测试通过 8 项，其中包含本切片的 2 项内存测试。随后根单元测试报告 1129 通过、1 失败、10 忽略；联系人 CLI 快照兼容失败已修复，未改动失败断言。该修复、连接级显示名读取及独立夹具接线仍待父任务复验；本地仅完成语法解析和静态差异检查。

其他业务域的 `resolve_username`、消息存储关联和归档元数据工作流仍属于后续切片；本次没有借联系人重构改写它们，也未变更公共 Args、IPC 生命周期或密钥持久化规则。
