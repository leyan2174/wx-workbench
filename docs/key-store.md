# 账号密钥存储

Windows 使用账号绑定、当前用户 DPAPI 加密的统一存储，管理账号密钥、逐库密钥和图片 AES/XOR 材料。普通配置只保存 `key_store` 路径引用，不写入新的明文密钥。

DPAPI 保护落盘数据，不隔离同一 Windows 用户运行的进程；原有宿主授权、路径检查和私有文件权限仍然适用。更换 Windows 用户或无法解密时明确失败，不回退旧文件。

## 数据库与音频边界

数据库密码材料区分可选账号材料 `account_key` 和逐库材料 `database_keys`，不要求每个账号都有前者。该分类不证明微信服务器保存方式、生成位置或所有版本的派生关系。图片 `image_key` 是实际使用的 AES/XOR 材料，独立保留。

不存在“语音级密钥”：从加密媒体数据库读取语音使用数据库密钥；取得 SILK 字节后，解码器只消费音频数据。SILK 头、封包、24 kHz 单声道 16 位 PCM 输出约定是非秘密格式知识，不进入 DPAPI Record、daemon 密钥快照或 worker MaterialChange，也不参与密钥轮换。不要将数据库路径索引或消息身份索引中的 key 理解成密码。

## 初始化与旧材料

先通过 `WX_CLI_CONFIG` 选定并核对账号配置，再显式获取当前密钥：

```powershell
wx init --force --key-provider memory
```

该命令授权当前账号的内存取钥，不导入旧材料；账号级捕获仍另需 `--force --key-provider account --restart-wechat`，详见[账号密钥](account-key-provider.md)。

- `all_keys.json` 和旧 `account_key.dpapi` 不再是读取来源，也不会被程序删除或生成迁移备份。
- 配置中出现 `image_aes_key` 或 `image_xor_key` 即明确拒绝，包括值为 null 的情况；错误不回显密钥值，也不代替用户改写配置。
- 已绑定账号的配置在初始化时缺省使用配置目录下的 `keys.dpapi`，仍执行原路径保护。未绑定配置旁有未知归属旧文件时继续拒绝，不能据此猜测账号。
- 旧 JSON 不能作为正式 `key_store` 加载；损坏、账号不符或无法解密的正式存储明确失败，不回退旧文件或静默扫描。图片记录只允许缺失或完整的 16 字节 AES 加 1 字节 XOR。
- 一字节 XOR-only 图片持久记录不受支持。即使 DPAPI 可正常解密、账号绑定正确，也以 `key_store_invalid` 拒绝整个快照及更新，不部分加载其中的账号/数据库密钥，不自动补 AES，不改写或删除旧文件。需要重新获取时，由用户为核对后的选中账号指定新的正式存储并显式授权获取。
- 完整材料的未验证标记仍可读取，不等于允许旧文件导入。媒体解码中的 XOR 参数、无图片材料时的正常默认值、V1 固定 AES 解码和无头 XOR 探测能力保留；它们不依赖一字节持久化格式。

初始化先保存验证后的加密材料，再发布配置引用。两个文件的发布不是整体事务；中间失败会明确报告，核对选中配置与已有正式存储后再重试初始化。普通业务不代替用户修复旧配置或读取旧文件。

既有诊断码 `key_store_migration_required` 暂保留机器协议兼容性，但仅表示旧材料不受支持或缺少正式存储配置，不提供迁移入口。是否保留历史文件由用户另行决定；普通删除不代表 SSD、备份或同步服务中的物理安全擦除。

## 身份与更新

`extract` 图片提取从同一账号的 daemon QueryLease 取得已加载图片材料，不再构造默认 provider 或隐式扫描内存。缺少 V2 图片 AES 材料明确失败，需先通过显式授权的图片密钥入口初始化；V1 的既有内容恢复规则保留。普通提取不更新秘密存储，输出采用共享受保护暂存发布。

一键解密、表情及全量导出的准备阶段只消费 daemon 已绑定账号的数据库快照。缺钥明确要求显式初始化，不再自动扫描进程内存或直接保存新材料；取钥仍使用上文的显式授权入口。外部删除或替换密钥库不会隐式刷新热快照，需要显式重载或重启 daemon；重启后缺失、损坏或账号不符的存储必须拒绝。

`keys_file` 配置字段继续作为既有运行身份与正式存储绑定锚点，不要改名或删除该字段。它不是业务密钥读取入口；账号绑定算法依赖该字段。

首次切换存储引用会改变配置版本。应显式停止对应旧后台并重新连接 MCP/Web 会话：

```powershell
wx daemon stop
```

普通类型化更新锁定加密存储，读取当前版本并原子发布新记录；可选预期版本拒绝过期写入。数据库更新替换该类型的完整清单，账号、图片更新保留其他类型。相同材料的重复更新不增加版本；不存在旧材料导入合并分支。临时文件仅含密文，发布前限制权限。

MCP 长期固定账号与配置身份，但只在每次操作期间持有阻止配置写入的锁。合法同账号密钥更新不改变配置指纹；配置文件替换、账号路径变化和存储引用变化均被拒绝。图片更新不再临时解锁或写回配置。

daemon 查询缓存记录密钥版本，后续请求发现更新后等待已有租约释放并刷新缓存；不会持有自己的查询读锁再等待失效写锁。

快照和临时缓冲区尽量清理密钥材料，不宣称消除了编译器、库或操作系统中的全部内存副本。密钥值不进入 `Debug`、诊断或任务结果。

## 后台任务

MCP 任务工具通过 service client 和任务 RPC 进入 daemon，再由 worker 执行。MCP 不自建队列、历史数据库、worker 或启动器；只读查询和同步图片发布与后台任务分别执行。

提交被接受后，任务归 daemon 管理。MCP 断连、工具调用取消和响应超时不隐式取消任务；只有明确的任务取消调用才进入 daemon 取消流程。响应丢失或结果不确定时，重试必须使用同一幂等键，再读取返回的任务标识。

后台重启仍将未完成任务按现有规则标为 `interrupted`，不是自动断点续跑。
